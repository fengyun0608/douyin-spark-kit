# 伙伴 SparkPal · 单仓库方案

> 一个仓库、一个 APK、一条命令自建。
> 范围：只做抖音火花，不做 QQ。

---

## 一、总体思路

```
一个开源仓库
  ├ app/      Flutter 客户端
  ├ server/   Go + Node 服务端
  ├ deploy/   docker-compose / nginx / 一键脚本
  └ docs/     逆向记录 + 部署文档

一个 APK
  首次打开 → 选服务器
    ├ 使用官方服务（我们托管，有订阅）
    └ 连接我的服务器（自建，功能全开）

客户端没有「官方版」分支
  所有能力由服务端 /api/spark/meta 返回
```

**为什么这样最干净**：

| 做法 | 问题 |
|---|---|
| 编译两个包 | 用户下错包；开源版容易被当成「免费版」去宣传 |
| 客户端硬编码官方判断 | 代码开源，判断能被改；且逻辑分叉难维护 |
| **服务端返回能力** | 客户端只有一条路径，谁都改不掉「收费在服务端」这个事实 |

## 三、首启流程

```
┌─────────────────────────────────────┐
│                                     │
│            [Logo 火苗]              │
│                                     │
│         让每一段火花              │
│           都不白攒                  │
│                                     │
│  ┌───────────────────────────────┐  │
│  │  使用官方服务          [推荐]  │  │  ← 默认高亮，主按钮
│  │  开箱即用，不用自己维护        │  │
│  └───────────────────────────────┘  │
│                                     │
│  ┌───────────────────────────────┐  │
│  │  连接我的服务器                │  │
│  │  自己部署，功能全开，无订阅    │  │
│  └───────────────────────────────┘  │
│                                     │
│  自建部署文档 >                     │
└─────────────────────────────────────┘
```

### 3.1 选「官方」

```
默认地址（无域名，IP 直连）
  https://114.66.28.185:48285/api/spark

→ GET /api/spark/meta  验证可达
→ 手机号登录
→ 绑定抖音
→ 开始用
```

**关于域名**：现在没有域名，官方地址写死 IP + 端口。
以后有域名时只改一处常量，并且允许多个备用地址（客户端按顺序探测）。

**首屏默认高亮「官方」**，自建作为次要选项（字号小一级，描边按钮）。转化优先。

### 3.2 选「我的服务器」

```
输入地址  http://192.168.1.10:3200
  或扫码（自建服务器启动时终端打印二维码，含地址+配对码）

→ GET /api/spark/meta  验证：
     · 能连上
     · 返回 sparkpal 标识（防止连错到别的服务）
     · 版本兼容
→ 输入配对码（服务器终端显示）
→ 拿 token
→ 绑定抖音
→ 开始用
```

### 3.3 地址校验（关键）

```json
GET /api/spark/meta
{
  "app": "sparkpal",
  "apiVersion": 1,
  "name": "我的伙伴服务器",
  "official": false,
  "billing": false,
  "quota": { "plan": "unlimited", "maxAccounts": -1, "maxFriends": -1, "maxDaily": -1 },
  "needPairCode": true
}
```

客户端只有**一条判断**：

```dart
// 只有服务端说 billing=true 才显示订阅入口
// 自建服务器固定返回 billing=false → 入口自动消失
if (meta.billing) showSubscriptionEntry();
```

**自建版 = 免费版，功能全开，没有任何付费入口。**
这样自建用户不会被「又要钱」恶心到，也让开源版和官方版的定位一眼分清：
```
官方   开箱即用，按绑定号数收费
自建   自己养服务器，永久免费，功能一样
```

## 四、官方与自建的差异（全部在服务端）

| 能力 | 官方 | 自建 |
|---|---|---|
| `official` | true | false |
| `billing` | true | **false（写死，不放计费入口）** |
| `quota.maxAccounts` | 1/3/20 | -1 |
| `needPairCode` | false | true |
| 扫码排队 | 有（资源有限） | 无（你独占） |

**客户端代码完全一致。**

## 五、服务器管理

### 5.1 多服务器

```
设置 → 服务器
  ● 伙伴官方         api.sparkpal.app
  ○ 家里 NAS        192.168.1.10:3200
  ＋ 添加服务器
```

切换后：
```
· 各自独立 token（换服务器要重新登录/配对）
· 缓存按服务器隔离（好友列表不串）
· 抖音绑定关系不跨服务器（因为 cookie 存在各自服务端）
```

**这一点必须提前告知用户**：换服务器 = 换一台机器存你的抖音登录态，好友勾选不跟着走。

### 5.2 连接第三方服务器提醒（必须做）

用户添加**非官方地址**时，强制弹一次确认，勾选后才能继续：

```
┌──────────────────────────────────────┐
│  ⚠ 连接第三方服务器需注意            │
│                                      │
│  你正在连接的服务器不是伙伴官方：    │
│      192.168.1.10:3200               │
│                                      │
│  连接后，这台服务器会保存：          │
│    · 你的抖音登录凭证（cookie）      │
│    · 你的好友列表与火花天数          │
│    · 你的发送记录                    │
│                                      │
│  请确认它是你自己部署，或你完全信任。│
│  伙伴官方无法为第三方服务器的数据安全│
│  负责。                              │
│                                      │
│  □ 我已了解并信任这台服务器          │
│                                      │
│        [ 取消 ]      [ 继续连接 ]    │
└──────────────────────────────────────┘
```

其它要求：
```
· 地址栏旁边常驻一个小标签：「第三方」
· 设置页顶部显示「当前服务器：伙伴官方 / 第三方」
· 官方地址 HTTPS；自建允许 http（局域网），但连接前提示「未加密」
· 切换服务器时再弹一次确认（数据不跟着走）
```

## 六、自建部署体验（这是转化的关键）

**必须一条命令。**

```bash
curl -fsSL https://get.sparkpal.app | bash
```

它做的事：
```
① 检查 docker
② 拉镜像
③ 生成随机密钥（JWT / cookie 加密）
④ 起 mysql + api + qr
⑤ 打印：
     ┌────────────────────────────────────┐
     │ 伙伴服务器已启动                    │
     │ 地址   http://192.168.1.10:3200     │
     │ 配对码 483920                       │
     │ 把这行填进 App 即可                 │
     └────────────────────────────────────┘
```

或者手动：
```bash
git clone https://github.com/.../sparkpal
cd sparkpal/deploy
docker-compose up -d
```

**资源要求写在 README 最显眼位置**：
```
最低  2 核 2G   （能跑，扫码慢）
推荐  2 核 4G   （扫码不排队）
磁盘  5G
```

## 十一、Logo

### 设计依据

参考 [Microsoft 图标指南](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-design)
与 [Apple WWDC 图标原则](https://developer.apple.com/videos/play/wwdc2017/822/)：
**单一隐喻、极简、不加装饰**。
火焰类图标的通行做法是「水滴轮廓 + 尖顶 + 软底」，
不要画缺口、不要加纹理，否则 24px 下会糊成一团。

### 三版

| 版本 | 文件 | 用途 |
|---|---|---|
| **1 单色火苗** | `assets/logo-1-solid.svg` | **主图标**（对比最强，24px 最清楚） |
| **2 双层焰** | `assets/logo-2-双焰.svg` | 深色版（启动页 / 品牌页 / 深色主题） |
| **3 火苗+火星** | `assets/logo-3-spark.svg` | 备用 / 活动图标 |

### 规格

```
画布     512×512，圆角 112（与 iOS/Android 自适应图标一致）
主色     #FF6B35 → #E5321F 渐变
深底     #131519
火星     #FFE6CC
安全区   内容居中，四周留 12% 边距（Android 自适应图标裁切要求）
```

### 多尺寸验证

`assets/logo-sizes.png` 展示 160 / 96 / 48 / 24 四个尺寸，

### UI 设计系统（企业风 · 双主题 · 无蓝 · 无 emoji）

**字体栈**
```
-apple-system, "PingFang SC", "HarmonyOS Sans SC", "Noto Sans SC",
"Microsoft YaHei", system-ui, sans-serif
font-variant-numeric: tabular-nums   数字等宽对齐（天数 / 时间）
```

**浅色**

| token | 值 | 用途 |
|---|---|---|
| bg | `#F5F6F8` | 页面底 |

| 主按钮 | `#101828` 底 + 白字 | 近黑，全站不用蓝 |

**深色**

**结构（沿用星语）**
```
圆角  卡片 8 / 输入 10 / 标签 7
字号  22 / 15 / 14.5 / 14 / 12.5 / 11.5 / 10.5
间距  4/8 网格：4 8 12 16 24 32
正文行高 1.75
```

**硬规则**
```
· 全站不用蓝色（主色近黑，火花砖橙）
· 一屏只有一个主按钮，次要操作用 ghost / 文字按钮
· 不用 emoji，也不用图标堆装饰；提示靠文字层级
· 头像一律真实图片，不用字母色块
· 首页不出现「最危险的火花」这类告警卡
  → 改成中性的「已有火花的好友 · 共 N 位」列表
  → 只陈述事实，不制造焦虑
· 深浅主题跟随系统，也可手动切换，两套 token 同源
```
